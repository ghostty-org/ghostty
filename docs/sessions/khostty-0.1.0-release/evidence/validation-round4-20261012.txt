## Why it doesn't work

The `sonar.qualitygate.wait` key in `sonar-project.properties`
controls whether the **scanner CLI** waits for the gate
result before exiting. It does NOT change the quality gate
itself and it does NOT affect the GitHub App integration's
check status.

For the SonarCloud GitHub App:
- The App invokes a scanner with its own configuration
- The scanner reads `sonar-project.properties` for project
  metadata (projectKey, sources, exclusions, etc.)
- The **quality gate is evaluated server-side in SonarCloud**,
  not by the scanner
- The App then reports the check status based on the
  server-side gate result
- The check is reported as **failed** if the gate fails,
  regardless of `sonar.qualitygate.wait`

`sonar.qualitygate.breakBuildOnQualityGateFailure` is the
Maven/Gradle equivalent and has the same scope: it only
affects the local build's exit code, not the App's check
status.

The SonarCloud GitHub App's check status is **only** affected
by the project's quality gate as configured in the SonarCloud
UI. For this fork, the relevant project is `KooshaPari_ghostty`
(verified in the failed-check URL:
`https://sonarcloud.io/dashboard?id=KooshaPari_ghostty&branch=main`).

## What the proper fix requires

Any of the following, in priority order:

1. **SonarCloud UI action (operator):** Set the quality gate
   for the `KooshaPari_ghostty` project to "None" or to a
   different gate that does not require Security Rating ≥ A
   on new code. This is a one-time UI change in SonarCloud
   that immediately fixes the App's check status on every
   push to any branch on the fork.

2. **Custom workflow (replace App):** Add a
   `.github/workflows/sonar.yml` that uses
   `sonarsource/sonarqube-scan-action@v3` with
   `-Dsonar.qualitygate.breakBuildOnQualityGateFailure=false`
   and a `SONAR_TOKEN` secret. Then remove the SonarCloud
   GitHub App from the repo. This is a code change but
   gives full control over the gate.

3. **Remove the SonarCloud GitHub App (operator):** Lose all
   SonarCloud signal on the fork, but eliminates the failing
   check. Cleanest if we don't care about SonarCloud.

4. **Accept the failing check (carry-forward):** Add the
   SonarCloud check to the list of "ignored for the fork"
   along with the override file. The check is non-blocking
   on the current default branch (the docs note that
   `qualitygate.wait=false` is a hint, not a hard block).
   **This is what the current state effectively is.**

The current `sonar-project.properties` file is the wrong
fix for the App integration. It works for self-hosted
SonarQube scanners and for SonarScanner CLI invocations,
but not for the SonarCloud GitHub App.
