## Finding 1 (HIGH): Dependabot #1 dismissal comment is factually wrong

**The original evidence file says:**

> `khostty-python/pyproject.toml` requires Python >= 3.10
> (CI uses 3.11/3.12). The 8.3.5/8.4.2 entries in uv.lock are
> gated to python_full_version < '3.9' and '==3.9.*' respectively,
> so they never resolve.

**Reality (verified 2026-10-12 23:07Z):**

`khostty-python/pyproject.toml` declares:

```
requires-python = ">=3.8"
```

Not `>=3.10`. The lock entries' resolution-markers are real and
correct, but the project's *declared* Python support floor is
3.8, not 3.10. That means 8.3.5 and 8.4.2 ARE valid resolutions
for any user who pip-installs `khostty-vt` on Python 3.8 or 3.9 —
they would get a vulnerable pytest in their test environment.

CI is unaffected: the GitHub Actions matrix uses `python-version:
'3.11'` (default) and `'3.12'` (publish-pypi), so CI always
resolves pytest 9.1.1 (post-fix; 9.0.3+ clears the
`< 9.0.3` vulnerable range). The 5-suite re-run on 2026-10-12
confirmed pytest 9.1.1 / 162/162 pass.

**The dismissal comment drafted in the prior file would be
defensible but is also factually wrong about requires-python.**
A reviewer checking the comment against the file would catch the
discrepancy and the dismissal could be reversed. This needs a
corrected comment before the operator clicks "approve" in the
Jcode TUI.
