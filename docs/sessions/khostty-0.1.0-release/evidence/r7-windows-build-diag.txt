The "win build doesn't work" claim is real and concrete: the script
stops at "ISCC.exe MISSING" and produces no .exe on this host. This is
NOT a script bug — it is the script's correct behavior in the absence
of Inno Setup. The Windows installer was last built+verified on
kooshapari-desk (2026-09-19).

To produce a new .exe on this macOS host, install Inno Setup via wine
and point KHOSTTY_ISCC at it. Two candidate paths:

  A. brew install --cask wine-stable + download ISCC.exe from
     https://jrsoftware.org/isdl.php, set:
       export KHOSTTY_ISCC="$HOME/.wine/drive_c/Program Files (x86)/Inno Setup 6/ISCC.exe"
     Then `bash packaging/windows/installer.sh` end-to-end. Verifiable:
     dist-release/CHECKSUMS.txt must list the new Khostty-0.1.0-windows-x86_64-setup.exe.

  B. Run packaging/windows/installer.sh on kooshapari-desk (Windows)
     directly. Same script, native ISCC. Outputs the .exe to
     dist-release/windows/stage/Khostty-0.1.0-win64/output/.

The current 0.1.0 release does NOT need a new Windows .exe to ship —
the existing one is install-verified and asset-checksummed. A
rebuild is a polish task, not a release blocker.
